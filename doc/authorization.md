# 認証・ログイン管理機構 要件定義議事録
1. プロジェクト概要
    - 家計簿アプリにおけるユーザー認証・ログイン管理機構の実装。

2. 認証の目的と範囲
    - 対象ユーザー: 一般ユーザー。
    - 提供サービス: 家計簿の登録・削除・編集・一覧取得。
        - ログインしているユーザー自身の情報のみ閲覧・操作可能。
        - 将来的に有料機能の追加を考慮するが、初期段階では実装しない。
    - 既存システム: なし（新規開発）。

3. セキュリティ要件
    - パスワード: 不要。GoogleOAuthの機構を使用する。
    - 家計簿データ: データベースでの保存時における暗号化は不要。
    - 通信経路: 必須でHTTPS/TLSを使用する。
    - トークン管理: アクセストークンとリフレッシュトークンは、両方HttpOnly属性およびSecure属性付きのCookieに保存する方針とする。
    - XSS対策: HttpOnly Cookie によりXSSからのトークン窃取リスクを大幅に低減するが、アプリケーション全体でのXSS対策（ユーザー入力のサニタイズ・エスケープ、Content Security Policy (CSP) の設定など）は引き続き徹底する。
    - CSRF対策: SameSite Cookie属性（LaxまたはStrict）の適切な設定に加え、CSRFトークンを用いた対策を導入する（例: ダブルサブリットクッキー方式）。
    - JWT管理:
        - アクセストークンは短寿命（例: 5分〜15分）に設定し、リフレッシュトークンは長寿命（例: 数日〜数週間）に設定する。
        - リフレッシュトークンのローテーション（一度使用したら新しいものに更新）を実装し、セキュリティを強化する。
        - サーバーサイドでのトークン失効（ブラックリストなど）の仕組みも検討する。
    - その他: ブルートフォースアタック対策（ログイン試行回数制限など）や、主要なWeb攻撃（SQLインジェクションなど）への対策は、Goのライブラリやフレームワークの適切な利用により講じる。

4. スケーラビリティ要件
    - MAU (月間アクティブユーザー): 1万人程度を想定。

5. IDプロバイダ選定と認証フロー
    - IDプロバイダ: Googleログイン を採用し、認証管理の開発・運用コストを最小限に抑える。
    - 認証フロー: Google Identity Services (GSI) を利用したIDトークン認証フローを採用する。
        - フロントエンド (React): GSI JSライブラリを使用してGoogle認証画面を表示し、Googleから発行されるIDトークンを受け取る。
        - Goバックエンド: フロントエンドから送信されたGoogleのIDトークンを検証し、トークン内のGoogleユーザーIDを基に、自社データベースのユーザー情報と紐付ける。
        - アプリケーション独自の認証: GoogleのIDトークン検証成功後、Goバックエンドがアプリケーション独自のJWT（アクセストークンとリフレッシュトークン）を生成し、HttpOnly Cookieとしてフロントエンドに発行する。以降のAPIリクエストではこの独自のJWTを使用する。

6. 技術スタック
    - バックエンド: Go
    - フロントエンド: React (TypeScript)

7. 今後の検討事項
    - Google Cloud Platform (GCP) の設定: OAuth同意画面、OAuthクライアントID（ウェブアプリケーションタイプ）、承認済みのリダイレクトURIの設定。
    - Goバックエンドの実装:
        - Google IDトークンの検証ロジック（Google Go SDKの利用）。
        - ユーザー情報（Google IDと内部DBユーザーIDの紐付け）のデータモデル設計。
        - アプリケーション独自のJWT（アクセストークン、リフレッシュトークン）の発行、署名、検証ロジック。
        - HttpOnly CookieのSet-Cookieヘッダ設定（Secure, SameSite属性含む）。
        - リフレッシュトークンのローテーションロジック。
        - CSRFトークンの発行と検証ロジック。
        - ログアウト時のトークン失効処理。
        - 各APIエンドポイントでの認証・認可ミドルウェアの実装。
        - APIリクエストに対するレートリミットの設定（Goアプリケーションのインメモリカウンタによる実装を優先して検討）。
    - React (TypeScript) フロントエンドの実装:
        - Google Identity Services (GSI) JSライブラリの組み込みとGoogleログインボタンの実装。
        - Googleから受け取ったIDトークンをGoバックエンドへ送信する処理。
        - Goバックエンドから発行されるHttpOnly Cookieの取り扱い（JavaScriptからは直接触らない）。
        - APIリクエスト時にCSRFトークンをリクエストヘッダに含める処理。
        - 認証状態（ログイン済みか否か）の管理と、それに基づいたUIの切り替え。
        - エラーハンドリングとリフレッシュ処理のフロー。
