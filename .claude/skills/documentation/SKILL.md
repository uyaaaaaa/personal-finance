# ドキュメント作成規約

## スコープ

本規約は、リポジトリ内のすべての `*.md` の**記述内容**を定義する。

以下は定義しない。

* ファイル配置とディレクトリ構成
* ADR(設計判断の記録)。却下した代替案を残すことが ADR の目的であり、本規約の原則と両立しない

## 原則

ドキュメントは、**最終的な設計を最初からそう計画していたものとして記述する**。想定読者は検討の経緯を一切知らない新規参画者とし、経緯を知らなければ意味が通じない文を残さない。

更新は差分の追記ではなく、その時点の最終形への全面的な書き直しとする。

## 書かないもの

* 変更履歴・経緯(「〜を追加した」「当初は〜だったが」「〜から変更」)
* 検討過程(「〜も検討したが見送った」「議論の結果」)
* 会話・会議・レビューへの参照(「前回の指摘により」「相談の結果」)
* 課題管理ツールのID参照(タスクID、チケット番号)
* 未確定であることの但し書き(「暫定」「後で決める」)。未確定なら、確定させるか、その項目自体を書かない

## 理由

書くのは、決定された仕様そのものと、その決定を選んだ理由である。

理由は、規定の文面だけでは同じ判断を再現できないときに限って書く。直感に反する規定、有力な代替案を採らなかった規定、破ったときに何が壊れるかが文面から読み取れない規定がこれにあたる。それ以外には添えない。規定の言い換えが増え、読み取れることが本文の量に対して減る。

同じ理由を項目ごとに繰り返さない。節の全体に効く理由は、節の末尾に1つ置く。

時系列に依存する記述(「当初は」「議論の結果」「却下された」)は理由ではなく経緯であり、書かない。

## 構造

* 各ドキュメントは冒頭にスコープ(何を定義し、何を定義しないか)を明記する
* スコープ外の項目は、それを担うものとあわせて挙げる。担い手が他のドキュメントのときは、担い手を書かず項目だけを挙げる
* ドキュメント同士の関係(上位・下位、どの文書が何を定めるか)を各ドキュメントに書かない。索引は `CLAUDE.md` が持つ
* 他のドキュメントの規約へ読み手を誘導しない。読むべき規約は `paths` による配置が決める。誘導のみを担う `paths` 付きのファイルは例外とする
* 規定の根拠となる上位の要件は、理由の一部として出典を示してよい

関係の記述を各ドキュメントに置かないのは、ドキュメントを追加・改名するたびに他のすべての冒頭を直すことになるためである。
