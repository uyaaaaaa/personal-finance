# TypeScript コーディング規約

## スコープ

本規約は `server/` 配下の TypeScript コードについて、機械検査で判定できない TypeScript 固有のコーディングの判断基準と、機械検査が担う範囲の宣言を定義する。

## 機械検査が担う範囲

| ツール | 担う範囲 |
|---|---|
| Biome（recommended） | lint とフォーマット |
| tsconfig strict | 型検査 |
| dependency-cruiser | 依存方向 |
| zod スキーマ | 境界の値の表現 |

これらで判定できる項目を本規約には書かない。決定論的に判定できる規約を新たに設けるときは、本文への追記ではなく lint ルール・型・スキーマ・テストでの表現を選ぶ（ドキュメント作成規約「置き場所」）。

## エラーの扱い

予期される失敗は戻り値で表し、例外は予期しない障害に限る。戻り値の型に載せることで、処理漏れを型検査で検出できる。

戻り値の形は次の1つを `domain` に定義し、各所で別形を作らない。

```ts
type Result<T, E> = { ok: true; value: T } | { ok: false; error: E }
```

* エラー側の型は文字列リテラルの union など、分岐の網羅性を検査できる形にする。`Error` や `string` にしない
* Result のライブラリを追加しない。この規模で必要なのはコンビネータではなく、失敗を型検査に載せることだけである
* 予期される失敗にあたるもの: パーサの未マッチ、入力の検証エラー、ポートが返す「見つからない」。予期しない障害にあたるもの: D1 の接続失敗、想定しない形の応答

## 値の表現

境界の表現は zod スキーマが定める。サーバー内部では次に従う。

* 保持する値と持ち回る値は境界と同じ表現とし、層ごとに変換しない。変換点が増えるほど、受け取った値が正規化済みかを呼び出し側が確認して回ることになる
* 金額は円の整数として D1 に保存する。実数型のカラムを作らない。2進浮動小数点は10進の金額を正確に表せない
* 日時は UTC で保存する。タイムゾーン情報を持たない日時を関数間で受け渡さない。パーサが読むメールの日時表記はローカル時刻であり、正規化しないと同じ値が文脈により異なる時刻を指す
* 日付（どの日の問答か、どの日の明細か）は `YYYY-MM-DD` で持つ。日時から日付を導出する箇所を1つに限る

## 外部から入る値

リクエストボディ・メール本文・D1 の行は、いずれも検証または変換を通してからモデル型にする。検証を通した値と通していない値を同じ型で扱わない。型注釈は実行時の形を保証せず、境界で検証しない限り strict な型検査は外部入力に対して無効である。

## テスト方針

* 素の Vitest で検証する対象: パーサ、domain のユースケース、ハンドラ（Hono の `app.request()` と、ポートのインメモリ実装を組み合わせる）
* @cloudflare/vitest-pool-workers を使う対象: `db` のアダプタと、マイグレーションの適用
* 新しいロジックは、まずポートを介した形で書けないかを検討する。テストの大半を高速な層へ寄せる
* パーサのテストは、抽出できる書式だけでなく、未マッチとなるメール（対象外の事業者、書式変更後）も対象とする。未マッチが戻り値で表れることが、原文保持の経路の前提である
