# TypeScript コーディング規約

## スコープ

本規約は `server/` 配下の TypeScript コードについて、機械検査で判定できないコーディングの判断基準と、機械検査が担う範囲の宣言を定義する。ディレクトリ責務・依存方向・不変条件は `.claude/rules/architecture/typescript.md` が定める。

## 機械検査が担う範囲

| ツール | 担う範囲 |
|---|---|
| Biome（recommended） | lint とフォーマット |
| tsconfig strict | 型検査 |

これらで判定できる項目を本規約には書かない。決定論的に判定できる規約を新たに設けるときは、本文への追記ではなく lint ルール・型・テストでの表現を選ぶ（CLAUDE.md「制約とコンテキストの置き場所」）。

## 値の表現

* 金額は円の整数として扱う。浮動小数点数にしない。2進浮動小数点は10進の金額を正確に表せないためである
* 明細の日時は UTC に正規化して保存する。タイムゾーン情報を持たない日時をコンポーネント間で受け渡さない。パーサが読むメールの日時表記とアプリの表示時刻はいずれもローカル時刻であり、境界で正規化しないと同じ値が文脈により異なる時刻を指すためである

## エラーの扱い

予期される失敗（パーサの未マッチ、入力の検証エラー）は戻り値で表し、例外は予期しない障害に限る。予期される失敗を戻り値の型に載せることで、処理漏れを型検査で検出するためである。

## テスト方針

* バインディングに依存しない対象（パーサ、ハンドラが呼ぶ関数、入力検証）は、素の Vitest と Hono の `app.request()` で検証する
* @cloudflare/vitest-pool-workers を使うのは、D1・Email を実際に使う対象に限る
* 新しいロジックは、まずバインディング非依存の形で書けないかを検討する。テストの大半を高速な層へ寄せるためである（技術選定「検証コマンド」）
