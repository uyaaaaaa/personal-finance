# TypeScript コーディング規約

## スコープ

本規約は `server/` 配下の TypeScript コードについて、機械検査で判定できない TypeScript 固有のコーディングの判断基準と、機械検査が担う範囲の宣言を定義する。言語によらない基準（命名・コメント・依存の追加）は `.claude/rules/coding/common.md` が、ディレクトリ責務・依存方向・不変条件は `.claude/rules/architecture/typescript.md` が定める。

## 機械検査が担う範囲

| ツール | 担う範囲 |
|---|---|
| Biome（recommended） | lint とフォーマット |
| tsconfig strict | 型検査 |

これらで判定できる項目を本規約には書かない。決定論的に判定できる規約を新たに設けるときは、本文への追記ではなく lint ルール・型・テストでの表現を選ぶ（CLAUDE.md「制約とコンテキストの置き場所」）。

## 値の表現

境界での表現は `.claude/rules/architecture/api.md`「値の表現」が定める。サーバー内部では次に従う。

* 保持する値と持ち回る値は境界と同じ表現とし、層ごとに変換しない。変換点が増えるほど、受け取った値が正規化済みかを呼び出し側が確認して回ることになるためである
* 金額は円の整数として D1 に保存する。実数型のカラムを作らない
* 日時は UTC で保存する。タイムゾーン情報を持たない日時を関数間で受け渡さない
* 外部から入る値（リクエストボディ、メール本文）は、内側へ渡す前に検証する。検証を通した値と通していない値を同じ型で扱わない。型注釈は実行時の形を保証しないため、境界で検証しない限り strict な型検査は外部入力に対して無効であるためである

## エラーの扱い

予期される失敗（パーサの未マッチ、入力の検証エラー）は戻り値で表し、例外は予期しない障害に限る。予期される失敗を戻り値の型に載せることで、処理漏れを型検査で検出するためである。

## テスト方針

* バインディングに依存しない対象（パーサ、domain の関数、入力検証、ハンドラ）は、素の Vitest と Hono の `app.request()` で検証する
* @cloudflare/vitest-pool-workers を使うのは、D1・Email を実際に使う対象に限る
* 新しいロジックは、まずバインディング非依存の形で書けないかを検討する。テストの大半を高速な層へ寄せるためである（技術選定「検証コマンド」）
* パーサのテストは、抽出できる書式だけでなく、未マッチとなるメール（対象外の事業者、書式変更後）も対象とする。未マッチが例外にならず戻り値で表れることが、原文保持の経路（`.claude/rules/architecture/typescript.md`「パーサの規約」）の前提であるためである
