# デザイン要件定義

## スコープ

本書は [要求定義](requirements.md) を上位文書とし、そこで定義された体験を実現する画面の設計を定義する。対象は、画面の一覧、各画面の構成要素と状態、画面間の遷移、通知の挙動、および表示に必要な判定基準である。

以下は定義しない。

* 視覚表現の詳細（配色、タイポグラフィ、余白、アイコン）と画面上の文言。実装時に各 OS の標準に沿って決定する
* 実現手段（アーキテクチャ、技術スタック）。要件定義で扱う

## プラットフォーム

iOS / Android のネイティブアプリケーションとして提供する。

画面の数、各画面の構成要素、状態、遷移は両 OS で共通とする。以下は各 OS の標準に委ねる。

* 戻る操作（Android のシステムバック、iOS のスワイプバック）
* タブバー・ナビゲーションバーの位置と見た目
* 数値キーボード、時刻ピッカーなどの入力コンポーネント
* 通知許諾ダイアログの表示作法

共通化するのは情報設計であり、操作作法ではない。OS 標準に準拠することで、ユーザーに操作の学習を課さず、実装も標準コンポーネントで完結する。

## 画面構成

タブ2つ（今日／履歴）を骨格とする。設定は履歴タブのヘッダから開く。

記録の閲覧は要求定義が主機能と定めるため、問答からの導線の先ではなくタブとして並置する。設定は日常的に開く画面ではないため、タブにしない。

画面は次の8つですべてとする。

| # | 画面 | 役割 |
|---|---|---|
| 1 | サインイン | アカウントの識別 |
| 2 | オンボーディング：転送先アドレス | 決済通知の転送設定の案内 |
| 3 | オンボーディング：通知時刻 | 問答の通知時刻の設定と通知許諾 |
| 4 | 今日 | 毎晩の問答と結果の提示 |
| 5 | 履歴：月 | 月次の振り返り |
| 6 | 履歴：日次明細 | 明細の閲覧・補正・固定費の指定 |
| 7 | 設定 | アカウントと通知の管理 |
| 8 | 設定：除外中の店 | 固定費指定の確認と解除 |

## サインイン

Sign in with Apple および Sign in with Google のみを提供する。パスワードによる認証は持たない。

保持するデータは店名・金額・日時のみであり、パスワードを預かる必然性がない。パスワード認証を持たないことで、パスワードの入力・再設定の画面が不要になる。

## オンボーディング

サインイン直後に次の2画面を順に表示する。完了するまでタブ画面へは進めない。転送が未設定のままタブ画面に到達すると、実績0件との突き合わせが起きて問答が成立しないためである。

1. **転送先アドレスの提示**。ユーザー固有の転送先メールアドレスを表示し、コピー操作を提供する。決済通知メールをこのアドレスへ転送する設定を、ユーザー自身のメール環境で行うよう案内する
2. **通知時刻の設定**。毎晩の問答の通知時刻を設定する（既定 21:00）。この画面で OS の通知許諾を要求する

通知時刻を初回に設定させるのは、習慣が形成されていない段階では初日の通知が最も重要であり、本人の生活時間と合わない時刻に既定値のまま通知することを避けるためである。通知許諾をこの画面で要求するのは、時刻を選ぶ文脈が許諾理由の説明を兼ねるためである。

転送設定の成否を確認するゲートは置かない。成否は次の決済通知が届くまで確認できず、ゲートとして機能しないためである。転送不備の検知は「今日」画面の実績未取得状態が担う。

## 今日

1画面で次の3状態を持つ。

### 回答前

通知時刻を含む案内と、問答へ進むボタンを表示する。通知時刻前でも自ら回答できる。通知は習慣の起点であり、回答の制約ではない。

問答へ進むと、金額フィールドと OS 標準の数値キーボードで、その日の裁量支出額を実額で入力する。画面表示と同時にフィールドへフォーカスし、キーボードが開いた状態で始める。

選択肢やスライダーではなく実額の直接入力とするのは、金額帯の区切りやスライダーの上限が推定のアンカーとして働き、推定そのものを歪めるためである。

### 結果

回答の直後、画面遷移を挟まず同一画面の差し替えで、次の6要素のみを表示する。

* 推定額
* 実績額
* 差分（実額）
* 的中／外れ
* 連続回答日数
* その日の日次明細への導線

遷移やモーダルを挟まないのは、フィードバックの即時性を体感として保つためである。連続回答日数はこの結果の中にのみ表示し、常時表示しない。問答をしていない時間帯に成績が視界に入ることは、精度を蓄積しないという要求定義の方針に反するためである。

結果は日の境界まで再表示でき、境界を越えると回答前に戻る。回答とズレは保持しないため、過去の結果を表示する手段はない。

### 実績未取得

その日の明細が0件の間は、問答を伏せて実績が未着である旨を表示する。実績が反映されていない状態でのズレはシステムの遅延を示すだけで、問答が成立しないためである。

明細0件は、支出がなかった日と、転送設定の不備や通知の遅延とを画面から区別できない。0件の日が3日続いたときは、転送設定の確認への導線をこの画面に1度だけ表示する。

### 問答の規則

* **日の境界**は 4:00 とする。3:59 までに開いた問答は前日分として扱い、結果の再表示も 4:00 までとする。0:00 で締めないのは、日付が変わった直後に開いた回答を落とさないためである。明細の日付は決済の日時に従う
* **対象は当日のみ**とし、過去の日に遡って回答できない。回答とズレは保持しないため、過去日の回答には行き先がない
* **的中の判定**は実績額の ±20% とする。ただし ±250円 までは実績額によらず許容する。割合のみでは少額の日に達成不能な判定となるためである。判定基準はユーザーが変更できない。基準の調整は当てにいく行動を誘発し、記録を最小限にするという前提と矛盾するためである
* **連続回答日数**は回答した日に伸びる。実績未取得で問答が伏せられた日は計算から除外し、伸ばしも途切れもしない。回答できない日が途切れとして数えられると、システム側の事情が離脱の理由になるためである

## 履歴：月

月の合計と日別リストを表示する。ヘッダの月表示を左右に送って月を切り替える。初期表示は当月。

合計は裁量支出と固定費の2段で示す。日別リストの行は日付とその日の裁量支出合計を示し、タップで日次明細へ遷移する。

グラフとカテゴリ別の集計は置かない。保持する項目は店名・金額・日時のみでカテゴリが存在せず、描けるのは日別の棒グラフに限られる。それは日別リストと同じ情報の再表現であり、置く価値がない。

## 履歴：日次明細

その日の明細を時刻順に全件表示する。行の要素は店名・金額・時刻。日合計は裁量支出と固定費の2段で示す。

固定費の行はラベルを付けた淡色表示とし、裁量支出と区別したうえで一覧に残す。固定費を隠すと家賃を含まない合計だけが残り、家計簿として成立しない。区別しないと、問答が対象とする額を画面から読み取れない。

問答の結果からの導線は、当日の本画面へ直接遷移する。

### 補正

明細の追加と削除ができる。追加の入力項目は店名・金額・日時の3つのみ。追加は現金支出などの捕捉漏れ、削除は決済通知の重複や与信・確定の二重計上に対する操作である。編集は提供しない。削除と追加で代替でき、画面を増やす価値がない。

### 固定費の指定

行から、その店を固定費として指定・解除できる。指定は同じ店名の明細すべてに、過去の明細を含めて適用される。固定費は毎月同じ店名で現れるため、店単位の指定なら操作は店ごとに一度で済む。過去に遡って適用するのは、指定の前後で月画面の裁量支出額が食い違うことを避けるためである。

## 設定

履歴タブのヘッダから開く。項目は次のとおり。

* 転送先アドレスの表示とコピー
* 通知時刻の変更
* 除外中の店の一覧（サブ画面へ）
* データの削除
* サインアウト

データの削除はアカウントの削除と同義であり、明細を含む全データを消す。実行前に確認を1段挟む。明細のみの全削除は持たない。実行後もアカウントと転送設定が残り、次の通知から明細が再び溜まり始めるため、用途が想定できない。個々の明細の削除は日次明細が担う。

## 設定：除外中の店

固定費として指定中の店名を一覧し、解除できる。指定は店名単位で過去の明細まで効くため、効果の範囲を確認して取り消せる場所を、明細の行とは別に持つ。

## 通知

* 毎晩1回、ユーザーが設定した時刻に送る。再通知は行わない。催促は、要求定義が浪費の抑制について排した介入と同種の圧力を、習慣の側に持ち込むためである
* タップで問答へ直行する
* 本文に金額を含めない。ロック画面に支出額が表示されることを避けるためである

## 画面遷移

```
サインイン → 転送先アドレス → 通知時刻の設定 → 今日
今日 ⇄ 履歴：月                  … タブ切り替え
今日（結果） → 履歴：日次明細（当日）
履歴：月 → 履歴：日次明細
履歴（ヘッダ） → 設定 → 除外中の店
通知 → 今日（問答）
```
